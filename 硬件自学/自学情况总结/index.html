    我提问了

    平台与路线选择 - DIY 数字键盘/小键盘到底该用 FPGA（达芬奇 A7）还是 MCU（STM32/ESP32-S3）？“用 FPGA 写小键盘是不是杀鸡用牛刀？” - FPGA 工程师与嵌入式工程师的工作差异、学习路径、就业与薪资的现实对比。 - 达芬奇 A7 为什么不能直接用数据线下载、必须用下载器？USB-SLAVE 与 USB-UART、HDMI_A/B 这些接口分别干嘛。

    具链安装与驱动疑难 - Vivado 安装“哪些组件要勾选”、线缆驱动（Digilent/Adept Runtime/飞特/CH340）装完仍然“黄色感叹号”的成因与排查顺序。 - 设备管理器里“USB Serial Converter”不识别、端口争用（串口监视器与板卡争抢）怎么办。 - Vivado 项目中 Sources 的分类、sim sources、design sources、问号与红叉的含义、如何“Refresh/Rescan Sources”、TCL Console 在哪开、如何用 TCL 重新整理工程。

    HDL 写法与数字电路原理 - D 触发器/JK 触发器/锁存器的本质区别与 Verilog 规范写法；wire/reg、过程赋值与连续赋值；端口声明的规则。 - 脉动计数器 vs 同步计数器、负沿/正沿触发的差异；P/T 使能的语义、主使能与级联使能的分工；Lookahead/Carry-select 的意义。 - 七段数码管译码（MC14495）逻辑、I LovE YOU 的布尔化简、数组化实例代替逐位实例化的写法。 - 计数器/加法器的 ripple、假路径识别与处理、进位跳跃加法器的“矩阵 vs 树形”结构怎么权衡布线与时延。

    存储器与时序 - 独立存储器芯片的地址/数据脚交互、读写时序为什么“总时长>2周期”、波形图怎么看、W 拉低/拉高分别代表什么。 - 组合逻辑为什么不应该驱动“跨拍”信号；为何“直通”可能带来外部延迟但并非总优。

    嵌入式与外设驱动（ESP32-S3 为主） - 官方示例里 UART0→IO43/IO44 的映射为何与板卡不一致；PlatformIO/Arduino Core 与 正点原子配套库的关系与取舍。 - I²C 屏、XL9555 I/O 扩展、LCD DC/IO_SEL/IO0 与 1-WIRE 的跳线关系；乱码/I²C 位址/上电初始化顺序导致的“黑屏”。 - USB HID 键盘、TFT ST7735 显示、按键矩阵的接法、INPUT_PULLUP 的选择、消抖策略与函数分层结构。 - VS Code 模式、只编译单个示例/子工程的方法，Copilot/格式化插件（如 Prettier）安装与触发时机。

    项目工程化与调试方法 - “为什么仿真能过、上板不亮”的系统性排查：原理图对表、约束文件、时序报告、探针/示波器验证顺序。 - Git/SVN、WSL 与工具链落盘位置、C 盘清理与大文件移动的做法。

    你学到了

    选型原则落地 - 小规模人机交互（4~10 键、简单显示）优先 MCU：上手快、外设丰富、功耗低、软件生态成熟；需要高速并行、严格时序或可重构流水线时再考虑 FPGA。 - “杀鸡用牛刀”的含义不仅是过度复杂，更是学习与调试成本/交付周期的不匹配。

    工具链与驱动排障闭环 - 设备不识别的三段论：线缆/供电与物理连接 → 设备管理器识别（VID/PID、端口）→ 驱动与上层软件（Adept/Digilent、FTDI/CH340、Vivado Cable）。 - Vivado 组件勾选与线缆驱动优先级：先操作系统设备识别，再谈 Vivado Hardware Manager。 - Sources 视图的“问号/红叉”并不等于文件丢失，常见是路径/库引用或仿真/综合作用域设置不当；TCL 能“复刻工程”，把 GUI 里“说不清楚的项目状态”转成可追溯脚本。

    规范的 HDL 与可综合思维 - always @(posedge clk) 的单时序域写法、异步输入要双触发器同步；组合逻辑与时序逻辑分离，避免隐式锁存与多驱动。 - 计数器模块化：主使能（master enable）负责全域开关，级联使能（ripple/terminal enable）负责阶段进位；用参数化与数组化实例简化多位结构。 - Lookahead/Carry-select 的核心是以面积换时延，并联计算多路进位，再以选择器合并，形成亚线性延迟的加法路径。

    存储器/时序的“波形—约束—实现”统一 - 读写至少覆盖地址稳定—片选—读/写—数据建立保持的完整窗口，“>2周期”来源是把时钟到 Q、总线传播、器件访问时间与保持时间全部计入。 - 假路径/多周期路径要在时序约束中明确标注，否则综合与布局布线会把它当作关键路径优化，反而引入错误。

    嵌入式驱动与连线管理 - UART0、I²C、SPI 在不同板卡上的默认引脚未必一致，以板卡原理图/变更说明为准；PlatformIO 的 board.json 与 variant 决定默认脚位。 - INPUT_PULLUP 配合按键下拉到 GND是最省事的接法；消抖要么时间门限（如 10–20 ms），要么状态机。 - TFT ST7735 的 SPI 初始化顺序、I²C 外设的地址/上拉/线长与黑屏、乱码强相关；IO0/IO_SEL 跳线改变启动模式/外设选择，上板前要逐一核对丝印与手册。

    工程化与调试方法论 - 形成“五步闭环”：规格—原理图—约束—仿真—上板；上板再按供电/时钟/复位/引脚/固件的顺序排查。 - 养成“一页总览表”：引脚表（功能/电压/上拉下拉）、外设地址、波特率、时钟树、关键时序；把“拍脑袋”的问题变成“对表就能定位”的问题。 - 工具与环境要“可复制”：TCL/脚本化工程、固定版本的驱动与依赖、Git/SVN 管理大文件，避免“换台电脑就炸”。
