1.**组合逻辑写得不完整（比如case），会推断出锁存器 (latch)**
- 当 `sel = 2'b11` 时，`out` 没有被赋值。
- 如果在组合逻辑 `always @(*)` 块里，某个信号 **在某些分支没被赋值**，综合工具会认为：需要“保留上一次的值”。 
- 保留旧值 = 需要存储功能 → 就会综合出 **锁存器 (latch)**。
- <font color="#b2a2c7">工程里一般不用锁存器</font>
- 所以在case之前，要给一个out的默认值

2.**if-else 和 case 在 Verilog 中是“逐条判断”的**，所以会引入 **优先级逻辑**。如果你本来只想做 **并行逻辑**，但写成 if-else，就会多出优先级电路。这可能导致电路复杂度增加、延迟变长、时序变差。
**解决方法**：- 这里的条件是 <font color="#b2a2c7"><b>互斥的 </b></font>(mutually exclusive)**：
- `i` 只能是 4'b0001、0010、0100、1000 之一 不可能同时满足两个条件。
- 因此综合工具会识别出来，优化成 **并行逻辑**（不再是优先级链）

3.顶层 ALU 模块:只做“连接与选择”，具体运算交给已经写好的子模块完成。包括：
- 对外引脚（输入 输出 控制信号）
- 中间量声明：子模块之间要互相传递信号，这些中间信号不会直接暴露到外部，所以在顶层要用 **wire** 声明（组合逻辑的连线）
- 子模块实例化：每次实例化都要写：
1. **模块名**（子模块类型，比如 `add32`）
    
2. **实例名**（一个具体拷贝，比如 `our_adder`）
    
3. **端口连接**（哪个信号接哪个端口，推荐用名字关联）。按名字连接 ```
   mux32three output_mux(
    .sel(f[2:1]),
    .out(r),
    .i0(add_out),
    .i1(sub_out),
    .i2(mul_out)
);```

6.异步清零中敏感条件同步异步不可混用
触发条件：**posedge** = positive edge = **时钟从 0 跳到 1 的瞬间**（上升沿）
 **negedge** = negative edge = **时钟从 1 跳到 0 的瞬间**（下降沿）
假设你想做 **异步复位的触发器**，常见写法是：
`always @(posedge clk or negedge rst_n)`
这里敏感列表里有两个信号：
`posedge clk` （表示在时钟上升沿触发）
`negedge rst_n` （表示复位信号从 1 → 0 时触发）
也就是说，这个 always 块会在 **时钟正沿** 或 **复位下降沿** 时被激活。

错误写法：always @(negedge clk or rst_n)
negedge clk 表示“下降沿触发”，但 rst_n 没有带 posedge/negedge，这表示对 rst_n 是电平敏感（只要它变化就触发，不管是 0→1 还是 1→0）
结果敏感列表里混了两种不同的触发条件：一个是“边沿触发”，一个是“电平触发”。
综合器看到这种写法，就可能推出 锁存器（latch） 或者 行为不明确的电路，跟你本来想要的“异步清零触发器”不一致。

10.同步外部的异步输入
```
reg l_sync1, l_sync2;
always @(posedge clk) begin
  l_sync1 <= L_async;   // 第1级：可能会短暂亚稳
  l_sync2 <= l_sync1;   // 第2级：给它一拍时间恢复，输出更稳定
end
wire L = l_sync2;       // 已同步到 clk 域
```
## 什么时候必须写（要同步）
- **外部引脚来的信号**：按钮/拨码、传感器中断、IR 接收、SPI/UART 的“数据就绪/中断”等（数据线本身用协议处理，下面详述）。
- **跨时钟域 (CDC)** 的**单比特控制**：例如 `ready/valid/irq/empty/full`、模块 A 的 `clkA` 发到模块 B 的 `clkB`。
- **复位释放**：外部复位或 PLL 锁定后释放复位，常用“异步断言、同步释放”的**复位同步器**（见下）。
- **来自“别的时钟或无时钟”的使能/标志**：比如你在慢时钟里做的去抖结果，喂给快时钟的 FSM。

11.关于存储器
- 写使能等控制信号要寄存 原因：OE/WE/CE 这些控制信号如果直接由组合逻辑生成，容易出现毛刺（瞬间抖动）。
- 多周期读/写比单周期更安全 
  - 单周期访问要求时钟周期 ≥ 2×tACC，很苛刻。 
  - 多周期 FSM把一次访问拆成 3 步
     - 写：先准备地址/数据，再拉低 WE，最后恢复。
     - 读：先给地址，等一拍，最后一拍采样数据。
  - **好处**：留足裕量，设计简单，容易在 FPGA 上成功。
- 分类
  - **SRAM**：不需要刷新，速度快，但密度低（用 6T 单元）。
  - **DRAM**：密度高（一格只要 1T1C），但必须刷新，读是破坏性的。 
  - **EPROM/EEPROM/Flash**：掉电保持，但写入很慢（需要高压 + 内部 FSM），适合做程序存储。
  - DRAM 密度更高（便宜、容量大），但需要专门的电容工艺。FPGA 内部通常用 **标准数字工艺**做存储单元，因此采用 **SRAM 技术**（即 FPGA 里的 Block RAM 实质上是 SRAM）
  - 存储器芯片内部包含很多 **模拟电路**（例如感应放大器、预充电电路）。 这意味着：噪声、电源抖动、PCB 布线质量 → 都可能影响存储器可靠性。提醒你：**在板级设计时，内存接口比纯逻辑电路要“娇贵”很多**。
- 总线上不能同时有两个驱动
  - 数据线是双向的：
  - 读：存储器驱动总线；
  - 写：FPGA/CPU 驱动总线。
  - 所以要用 **三态 (Hi-Z)**(高阻抗) 控制，确保任意时刻只有一方在驱动。
- ## 同步存储器 → 更高吞吐
  - 异步 SRAM：外部电路要严格对时序，难以跑高速。
  - 同步 SRAM：加时钟，接口更规则，可以用流水线和 ZBT 技术提升带宽。
  - 代价：可能多 1 拍延迟（流水线输出），但频率能大大提升。
